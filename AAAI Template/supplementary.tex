\section{Training Algorithm and Hyperparameters}
\label{app:hyperparameters}

\begin{algorithm}[H]
	\caption{HiVA Training}
	\label{alg:training}
	\begin{algorithmic}[1]
		\STATE \textbf{Phase 1 (BC):} collect value-aware asset-defense demonstrations; train tactical policy $\pi_\phi$ by cross-entropy
		\STATE Initialize centralized critic $V_\psi$
		\FOR{iteration $= 1$ to $T$}
		\STATE Collect rollouts: every $T_{\text{macro}}$ steps the commander assigns each agent a threat-weighted asset; $\pi_\phi$ acts with $R$ message rounds
		\STATE $r_t \leftarrow$ Equation~\ref{eq:reward} of the main paper
		\STATE Compute GAE advantages using $V_\psi$
		\STATE Update $\pi_\phi, V_\psi$ by clipped PPO with an entropy bonus
		\ENDFOR
	\end{algorithmic}
\end{algorithm}

\section{Statistical Test Details}
\label{app:statistics}

Comparisons use per-seed means ($n=5$). Against deterministic heuristics we use a one-sample $t$-test; against learned baselines, Welch's $t$-test. At five seeds a bootstrap over seed means is no better resolved than the $t$ interval, so we report the latter. We report Cohen's $d$ with a \textbf{pooled} standard deviation, and we \emph{omit} $d$ where a comparator has zero variance, reporting a raw difference with a confidence interval instead, since a standardized effect size against a zero-variance arm is an artifact of the divisor.

\paragraph{ISR intervals.} We report 95\% $t$ intervals on seed-mean ISR for the rows of Table~\ref{tab:main_results} of the main paper whose per-seed values were retained. Saudi: CommNet $[0.550, 0.814]$, MAPPO $[0.496, 0.888]$, HiVA $[0.737, 0.881]$. California: CommNet $[0.090, 0.706]$, MAPPO $[0.487, 0.761]$, HiVA $[0.798, 0.866]$.

Four of the six primary comparisons survive Holm correction. \textbf{Saudi vs.\ CommNet does not} (adjusted $p = 0.096$), and neither does Saudi vs.\ MAPPO. Accordingly, the abstract and Section~\ref{sec:results} of the main paper claim significant improvement over the communicating baseline on California only. Every other $p$-value in this paper, including all ablation tests and the learned-commander comparison, is exploratory and uncorrected. We report Welch's test on $n = 5$ without a normality check; a Wilcoxon signed-rank test would be more defensible at this sample size. No significance test is reported for ISR anywhere in this paper: the ``best average WEL and ISR'' claim is supported by point estimates and confidence intervals for ISR, and by hypothesis tests for WEL only.

\section{Simulator: Physics versus Wrapper}
\label{app:simulator}

To avoid overstating what is physically validated, we delineate which components come from Cell2Fire and which are ours.

\paragraph{Cell2Fire (validated spread computation).} Fire spread is computed by the Cell2Fire C++ engine~\citep{pais2021cell2fire}, implementing the Canadian Forest Fire Behavior Prediction (FBP) system: FBP fuel types mapped from remote-sensing normalized difference vegetation index (NDVI) data, wind- and slope-driven directional rate of spread, one fire period equal to one simulated minute, and stochastic spread governed by the rate-of-spread coefficient of variation. We invoke it through an interactive stdin/stdout step protocol. As Section~\ref{sec:limitations} of the main paper records, the engine is validated at a $100$\,m operating scale that our landscapes do not respect.

\paragraph{Custom wrapper (not Cell2Fire, not FBP).} The following are ours and should not be read as validated fire physics: (i) the suppression and treatment action model, which is not calibrated against real fireline production rates and provides no mapping from an agent step to a crew-hour or a retardant drop; (ii) the infrastructure cascade model, a per-neighbor ignition probability of $0.1$ when an asset cell burns, which is a wrapper parameter and not an FBP concept; (iii) the infrastructure-weighted reward of Equation~\ref{eq:reward} of the main paper; and (iv) the PettingZoo \texttt{ParallelEnv}~\citep{terry2021pettingzoo} multi-agent layer with action masking, where the treat action is masked unless the agent stands on an unburned fuel cell, movement is unmasked, and moves across the grid boundary are clipped to no-ops. Each agent step advances the simulator by $30$ fire periods.

\section{Compute and Reproducibility Disclosure}
\label{app:compute}

All reported experiments are CPU-only. No GPU or CUDA was used for any training or evaluation run: the launcher sets \texttt{CUDA\_VISIBLE\_DEVICES} to the empty string and uses one thread per worker, and all released checkpoints are serialized as CPU tensors.

\begin{itemize}\itemsep1pt
	\item \textbf{Execution environment:} Google Colab CPU instances, six training jobs concurrently, one thread each.
	\item \textbf{Software:} Python 3.12.3; PyTorch, NumPy, Gymnasium, PettingZoo, SciPy, pandas, and Matplotlib at the exact versions pinned in the released \texttt{requirements.lock}, which is authoritative and installs cleanly in a fresh virtual environment.
	\item \textbf{Wall clock (training):} each learned run completed $100$k environment steps in $34.5$--$47.5$ minutes (mean $41.3$) under six-way concurrency.
	\item \textbf{Wall clock (evaluation):} one evaluation episode costs $0.6$--$1.2$\,s single-threaded, so the full main-results evaluation ($1{,}425$ episodes) takes about $25$ minutes per region.
	\item \textbf{Seeds:} five training seeds $\{42, 1042, 2042, 3042, 4042\}$; each checkpoint is evaluated over five held-out seed groups. Training and evaluation draw from disjoint reset streams: training reset seed $=$ $\text{seed} \times 10^5 + \text{episode}$, giving values in the millions; evaluation reset seed $=$ $\text{group} + 10^5 + \text{episode}$, giving values near $10^5$. The asymmetry between the two formulas is intentional and is what guarantees the streams cannot intersect.
\end{itemize}

A release manifest binds every checkpoint and result artifact to its SHA-256 hash.

\section{Data Provenance}
\label{app:data}

The two regions are built from public remote-sensing sources over a June 2025 window. We do not redistribute the raw data; it is downloaded from the providers and processed deterministically into $32\times32$ Cell2Fire landscapes (converter \texttt{wildfire\_marl.data.to\_cell2fire}; every landscape carries a \texttt{conversion\_report.json} binding it to its input hashes).

\begin{itemize}\itemsep1pt
	\item \textbf{Regions:} Saudi Eastern Province (lon/lat $[45.5, 23.5, 50.5, 28.5]$) and Northern California (lon/lat $[-124.5, 36.5, -119.0, 41.5]$), CRS EPSG:4326, north-up. These extents span roughly $500 \times 553$\,km and $476 \times 553$\,km respectively; see Section~\ref{sec:limitations} of the main paper for the resolution consequences.
	\item \textbf{Fuels:} MODIS NDVI mapped to Canadian FBP fuel classes via fixed, region-independent thresholds, which we declare as a sensitivity parameter.
	\item \textbf{Weather:} ERA5 June-2025 extracts converted to hourly \texttt{Weather.csv}; Fire Weather Index (FWI) codes from the standard Canadian Forest Fire Danger Rating System (CFFDRS) equations. Wind direction is the meteorological from-direction.
	\item \textbf{Topography:} SRTM digital elevation model converted to per-cell slope percent and uphill azimuth in the FBP convention.
	\item \textbf{Ignitions:} NASA FIRMS detections restricted to burnable cells, detection-count-weighted, with disjoint train and evaluation seed streams.
	\item \textbf{Infrastructure criticality:} a \emph{stylized} layer, Gaussian value falloff around public infrastructure locations. These are not measured economic valuations, and WEL is therefore not currency. See Section~\ref{sec:impacts} of the main paper.
	\item \textbf{Known data debt:} the raw California NDVI GeoTIFF was not archived, so the released California NDVI is reconstructed under a declared linear assumption. We flag this because California is the region carrying the results that survive multiplicity correction, and the fuel map determines spread, which determines WEL. The released landscape and all reported results are internally consistent and reproducible from the released artifact; re-deriving the fuel map from a freshly downloaded GeoTIFF is a prerequisite for reproducing them from the original source imagery.
	\item \textbf{Release:} code, configs, checkpoints, and generated landscapes are released with a SHA-256 manifest.
\end{itemize}
