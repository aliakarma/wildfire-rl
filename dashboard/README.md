# Wildfire-MARL Results Dashboard

Static, single-page results dashboard for the AAAI submission.
React 18 + TypeScript + Vite + ECharts,
bilingual (English / Arabic with full RTL), two designed themes, hash routing, no backend.

**Every displayed number is generated at build time from the frozen artifacts** —
`results/wildfire_phase3_multiseed/`, `results/wildfire_phase4/`, `results/wildfire_phase6/` — never hand-typed.
All three directories are fingerprint-gated: the build script re-hashes each one and
aborts on any mismatch with the constants in `EXPECTED_FINGERPRINTS`
(`scripts/build_dashboard_data.py`). A re-freeze of any directory
(`python scripts/freeze_results.py <dir>`) must update that dict — it is the single
source the consistency checker imports.

## Workflow

```bash
# --- Windows or WSL: data + site -------------------------------------------------
# 1. Regenerate dashboard data (re-hashes all three frozen dirs first; aborts on mismatch).
#    --copy-media copies rollout media + the paper PDF into public/media/ (MP4 preferred
#    when compress_media.py has run). Writes are idempotent.
python scripts/build_dashboard_data.py --copy-media

# 2. Release gate: dashboard JSON == frozen summaries == paper headline values.
#    --release additionally requires every media reference AND replay to exist on disk.
python scripts/check_dashboard_consistency.py --release

# 3. Develop / test / build the site.
cd dashboard
npm install
npm run dev        # local dev server
npm test           # format rules + en/ar locale parity (vitest)
npm run test:e2e   # axe-core matrix: 10 routes × en/ar × light/dark (playwright)
npm run build      # typecheck + production build into dist/

# --- WSL venv only: simulation-backed artifacts ----------------------------------
# Tier-2 interactive replays (per-step frame JSON, self-verified against the frozen
# per-episode CSVs — replays are provably the reported rollouts):
python scripts/export_replay_frames.py --skip-unverified

# MP4 siblings for the rollout GIFs (10–20× smaller; media index prefers them):
python scripts/compress_media.py

# --- Release --------------------------------------------------------------------
# Arabic review deck for the native-speaker gate (§10.3):
python scripts/make_ar_review_deck.py          # -> docs/ar_copy_review.md

# Review-channel deploy (all gates, then Netlify; dry run without --deploy):
bash scripts/deploy_review.sh [--deploy]
```

CI (`.github/workflows/ci.yml`, job `dashboard`) runs the consistency check (including
replay re-verification), unit tests, the production build, the axe-core accessibility
matrix, Lighthouse budget assertions, and an anonymity grep over `dist/`.
`public/robots.txt` disallows all crawling for the review channel — replace it for the
camera-ready deploy.

## What is committed vs generated

| Path | Committed? | Notes |
|---|---|---|
| `src/`, `e2e/`, `tests/`, configs | yes | application source + test suites |
| `public/data/*.json` | yes | emitted by `build_dashboard_data.py`; committed so the site builds without Python (CI re-verifies consistency) |
| `public/data/replays/*.json` | yes | Tier-2 frame data (~30 KB each), emitted by `export_replay_frames.py` in WSL; endpoints re-verified in CI |
| `public/data/downloads/` | no | copies of the frozen CSV/manifest artifacts, regenerated by the build script |
| `public/media/` | no | rollout MP4s/GIFs + snapshots, copied by `--copy-media`; repo policy forbids committing large binaries |
| `node_modules/`, `dist/` | no | standard |

## Design decisions (documented)

- **Plain CSS tokens instead of Tailwind.** The guide's reasons for Tailwind (single
  `:root` token block, logical properties for RTL) are fully met by
  `src/theme/tokens.css` with zero extra dependencies ("dependency-light" is governing
  principle §2.8). No `left`/`right` properties are used anywhere.
- **Gallery media is MP4-first, click-to-play** (not autoplay-on-scroll GIFs): H.264 is
  10–20× smaller than the archival GIFs; the poster loads first and video only on demand
  (also satisfies `prefers-reduced-motion`). GIFs remain on disk as the archival format.
- **Replay frame encoding** uses sparse cell-index deltas instead of the guide's
  illustrative RLE — equally compact for 32×32 grids and trivially decodable.
- **`greedy_risk` has no Tier-2 replay**: its seed-42/episode-0 rollout is not
  reproducible in isolation with the current tree (trajectory-level statistics diverge
  from the frozen row while terminal WEL/ISR saturate identically — recorded in
  `public/data/replays/index.json` under `skipped_unverified`). Worth investigating
  before camera-ready; every published replay is verified against the frozen record.

## Release checklist (§16 of the guide)

- CI green: consistency (+replays), unit tests, build, axe matrix, Lighthouse, anonymity grep.
- Native-Arabic sign-off completed in `docs/ar_copy_review.md` (regenerate with
  `scripts/make_ar_review_deck.py`; the vitest parity suite checks structure only).
- `bash scripts/deploy_review.sh` dry run green, then `--deploy` to the neutral domain.
